Error 32 MatchNotExhausted means “already exhausted” on the extraction path (opposite meaning).
路由比较的 xUDT 是 (数量, type) 元组（parse_xudt 读 data[0..16]），因此 xUDT 模式下任何改变 xUDT 数量的 Match 更新都会落入 40 UnknownState；提取 / 取回 / 注资实际只对 CKB 模式可达。这是代码行为，非本页推断的规则。Routing compares xUDT as an (amount, type) tuple (parse_xudt reads data[0..16]), so in xUDT mode any Match update that changes the xUDT amount routes to 40 UnknownState; extraction / withdraw / inject are in practice only reachable in CKB mode. This is code behaviour, not a rule inferred by this page.
输出 Opticrum cell 按 “第一个 lock code_hash 相同且 hash_type = type 的输出” 查找，不比较 args：同一交易中有多个 Opticrum cell 时可能取到别的 cell。lock 不检查任何签名，授权仅靠 “对方 lock hash 出现在输入中”。The output Opticrum cell is “the first output whose lock has the same code_hash and hash_type = type”; args are not compared, so with several Opticrum cells in one tx another cell may be picked. The lock checks no signature; authorization is only “that party’s lock hash appears among the inputs”.
