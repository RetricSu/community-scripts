The check order is fixed: 10 → 21/14 → 11 → 12 → 13 → (bound: 23) → 15 → (bound: 22) → 16–20.
只读取 group 第 0 个输入的 witness：同一 group 的多个 cell 用一份证明一起解锁。generic 模式不检查输出，witness 可被任何看到它的人重放（README 也如此说明）；bound 模式用 tx_hash 绑定整笔交易。Only the witness of group input 0 is read: several cells in one group unlock with one proof. Generic mode checks no outputs, so the witness is replayable by anyone who sees it (as the README states); bound mode binds the whole tx via tx_hash.
16–20 来自 groth16-ckb verifier-core（rev e969ad1）的 VerifyError；VK 在 zk-Lock 中是原始 arkworks 字节，而不是 groth16-ckb 类型脚本使用的 molecule Groth16VerifyingKey。16–20 come from groth16-ckb verifier-core (rev e969ad1) VerifyError; in zk-Lock the VK is raw arkworks bytes, not the molecule Groth16VerifyingKey used by the groth16-ckb type script.
解码器离线检查：args 长度、witness 长度、pi_commitment、bound 模式的 pi[0]；VK cell_dep 查找与 Groth16 配对检查无法离线完成（NOT_CHECKED）。项目自述为测试网 / 未审计。The decoder checks offline: args length, witness length, pi_commitment, and pi[0] in bound mode; the VK cell_dep lookup and Groth16 pairing cannot be done offline (NOT_CHECKED).
